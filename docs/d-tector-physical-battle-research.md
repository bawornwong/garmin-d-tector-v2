# D-Tector sensor inputs and Spirit Power

The physical D-Tector's three sensor moments are a D-Code input sequence, not a way to bypass Spirit Power. The first motion starts input; the next two LED windows carry the two-bit attack code. The Bandai D-Tector instruction booklet describes the D-Code attack under **Battle Call**, where a Digimon is summoned from a D-Dock. Under **Spirit On**, it says to select an attack type with the buttons and explains that enough Spirit Power is required. **Digi-Power** uses D-Code to borrow a D-Dock Digimon's power for a single attack; it is a separate Spirit command. Sources: [scanned Bandai English instruction booklet, printed pp. 7–10](https://drive.google.com/file/d/1jSD5pXbV7YJ5HExr-oSOl5GEnNjQ1qE0/view?usp=drive_link), [Thai instruction text, sections 5.3.1 and 6.3.2](https://www.kudson.com/D-tector.html).

The [Unity source Battle.cs](https://github.com/kaisadilla/D-Tector-v2/blob/4672490f2d7ff41389da9414ed263e55a5418958/Assets/Scripts/Logic/Apps/Games/Battle.cs) implements the same distinction: `CallType.SpiritEvolution` sets `attacksCostSP` and `SubmitTurn` charges `GetSpiritCost(playerLevel)` on each attack; `CallType.RegularCall` instead gives 3 Spirit Power after each turn. `CallType.AncientEvolution` charges once at summoning rather than per attack. The [Garmin port](../app/source/Apps/Battle.mc) copies these branches. This Ancient behavior is established by the software source; the scanned booklet does not establish it for every physical D-Tector revision.

Conclusion: ordinary Spirit attacks cost Spirit Power in the source and port. The sensor pattern the player remembers selects an attack for Battle Call; it does not provide free Spirit attacks. The Garmin port chooses attack types with its controls because the physical D-Code sensor interaction was adapted to the watch.
