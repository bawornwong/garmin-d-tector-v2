# 12. Verification compares against generated references, never transcriptions

Date: 2026-09-06

## Status

Accepted

## Context

Nothing specifies this game's behaviour except its own code. "Does the port match?" therefore means "does it match the source", and the source has to be *run* to answer that.

The first golden trace for an animation was written by hand: a person read the C# and transcribed it into Python. Doing that 60 times repeats the translation risk twice over — and the hand-written trace was in fact wrong, emitting a `clearAnimParent` event the real code never produces because `ClearAnimParent()` iterates an empty list.

## Decision

Every reference is **generated by running the original's own code or reading its own data**, never transcribed:

- **Animations**: 485 lines of stubs let the *unmodified* `Animations.cs` compile and run outside Unity under .NET, tracing every builder call and accumulating every `WaitForSeconds`.
- **Numerics**: a C# program reproducing Unity's `float`/`Mathf` semantics sweeps every formula whose result a floor boundary can change.
- **Sprites and glyphs**: the packer unpacks its own output and diffs it pixel by pixel against the source PNGs.
- **Data**: every record is read back off the device and diffed against the source JSON.

All of these run in CI, not once.

## Consequences

Current results:

| Check | Result |
|---|---|
| Coroutines traced from the real source | 53 / 53, 6,911 events |
| Animation events against the golden trace | 150 / 150 |
| Sprite round-trip | 2,423 / 2,423 |
| Glyph round-trip | 113 / 113 |
| Database fields read back from the device | 9,488 / 9,488 |
| Numeric parity, C# against Monkey C | 6,059 values, zero differences |

- The numeric sweep matters most: two formulas land with **zero margin** on floor boundaries — every perfect cube — and still agree, which is the strongest available evidence that this device's `Math.pow` is IEEE-754 single precision. The thinnest real margin is `GetExperienceGained(45, 50)` at about 6 ULP.
- These checks are cheap and their absence is invisible, which is exactly why they must be automated rather than remembered.
