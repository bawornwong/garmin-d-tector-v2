# เสียงต้นฉบับ D-Tector บน Garmin Venu 4

ตรวจสอบ 2 ตุลาคม 2026 สำหรับ Venu 4 45 mm (`venu445mm`) และ Connect IQ SDK 9.2.0. เป้าหมายคือให้เสียงประกอบของเกมดังตามเหตุการณ์ โดยใช้ **MP3 ต้นฉบับหรือโน้ต/ทำนองที่ถอดจากต้นฉบับ** ไม่ใช้เสียง Garmin ชุดอื่นแทน ตัวเลขความเป็นไปได้ข้างล่างเป็น **การประเมินทางวิศวกรรม** ภายใต้เงื่อนไขที่ระบุ ไม่ใช่อัตราความสำเร็จที่ Garmin รับรองหรือผลทดสอบบนฮาร์ดแวร์ทุกทางเลือก

## ข้อสรุป

**ถ้าเสียงต้องออกจากลำโพง Venu 4 ตามเหตุการณ์ขณะเล่นเกม Connect IQ ตัวนี้: ยังไม่มีทางที่ใช้งานได้จริงด้วย API ปัจจุบัน** แม้ตัวนาฬิกาจะเล่น MP3 ผ่านลำโพงได้ แต่ความสามารถนั้นอยู่ในระบบ Music/Audio Content Provider ซึ่งไม่มี API ให้ watch app สั่งเล่นเอฟเฟกต์ตามเหตุการณ์ในเกม [คู่มือ Venu 4: Music](https://www8.garmin.com/manuals/webhelp/GUID-2CF5620C-E585-4E0A-9CC3-9565533EEE4D/EN-US/GUID-8702C05F-0915-455A-AABA-079D8374FCD8.html), [Toybox.Media](https://developer.garmin.com/connect-iq/api-docs/Toybox/Media.html), [Garmin: Audio Content Provider](https://developer.garmin.com/connect-iq/connect-iq-faq/how-do-i-create-an-audio-content-provider/)

**ถ้ายอมให้เสียงออกจากโทรศัพท์หรืออุปกรณ์เสียงเสริม** มีทางเล่น MP3 เดิมแบบตรงไฟล์ โดยส่งเพียงรหัสเสียงจากเกม ไม่ส่งสตรีมเสียงผ่าน BLE: แอปคู่บนโทรศัพท์เป็นทางที่ใช้ฮาร์ดแวร์น้อยที่สุด; อุปกรณ์ BLE เล่น MP3 เป็นทางที่ไม่ต้องพึ่งโทรศัพท์ระหว่างเล่น [Toybox.Communications.transmit](https://developer.garmin.com/connect-iq/api-docs/Toybox/Communications.html), [Toybox.BluetoothLowEnergy](https://developer.garmin.com/connect-iq/api-docs/Toybox/BluetoothLowEnergy.html), [DFRobot MP3 module](https://wiki.dfrobot.com/dfr0299/docs/20905)

## หลักฐานที่กำหนดขอบเขต

- โปรเจกต์นี้เป็น `type="watch-app"`, target `venu445mm` ใน [manifest](../app/manifest.xml). ต้นฉบับมีไฟล์ MP3 51 ไฟล์ใน [Assets/Audio ของโครงการเดิม](https://github.com/kaisadilla/D-Tector-v2/tree/master/Assets/Audio); โปรเจกต์นี้เก็บชื่อเหตุการณ์เสียงและข้อมูลโน้ตที่ถอดจากไฟล์เดิมใน [SoundData.mc](../app/source/Data/SoundData.mc) และ [ADR 13](adr/0013-sound-is-tones-generated-from-the-source.md). การตรวจใน repository เดิมนับไฟล์ `*.mp3` ได้ 51 ไฟล์; จำนวนไฟล์ที่มี call site จริงน้อยกว่านั้น
- `Attention.playTone()` ระบุทั้ง `TONE_*` ที่ Garmin บันทึกไว้ล่วงหน้าและ `ToneProfile(frequency, duration)` ที่ออกแบบสำหรับลำดับโน้ต เอกสาร API แสดง Venu 4 เป็นอุปกรณ์ที่รองรับ แต่ **รายการนี้ไม่ได้ยืนยันว่า Venu 4 สังเคราะห์ `ToneProfile` ได้จริง** [Toybox.Attention](https://developer.garmin.com/connect-iq/api-docs/Toybox/Attention.html), [ToneProfile](https://developer.garmin.com/connect-iq/api-docs/Toybox/Attention/ToneProfile.html)
- เจ้าหน้าที่ Connect IQ ของ Garmin อธิบายว่าอุปกรณ์ที่เปลี่ยนจาก tone generator เป็นลำโพงจะเล่นได้เฉพาะเสียง `TONE_*` ที่บันทึกไว้ล่วงหน้า; API `hasToneSupport` แยกสองกรณีนี้ไม่ได้ และ simulator อาจเล่น `ToneProfile` ได้ทั้งที่นาฬิกาจริงไม่เล่น เขาระบุเพียงว่ามีการหารือเรื่องรองรับ arbitrary tones บนลำโพง ยังไม่มีคำมั่นเรื่องกำหนดส่ง [คำตอบเจ้าหน้าที่ Garmin](https://forums.garmin.com/developer/connect-iq/f/discussion/405695/the-toneprofile-does-not-work-on-venu3s/1908427), [คำตอบต่อเรื่องเสียงกำหนดเอง](https://forums.garmin.com/developer/connect-iq/f/discussion/405695/the-toneprofile-does-not-work-on-venu3s/1909456)
- การลองบน **Venu 4 จริง** ที่บันทึกไว้ใน [ADR 13](adr/0013-sound-is-tones-generated-from-the-source.md#venu-4-hardware-amendment-2026-09-28) ได้ยิน `TONE_*` แต่ไม่ยินเสียงเกมที่ใช้ `ToneProfile`; simulator เคยเล่นได้ จึงไม่ควรใช้ผล simulator เป็นหลักฐานว่าเสียงเดิมดังบนนาฬิกา การตั้งค่า `tonesOn` ของเครื่องเป็นอีกเงื่อนไขหนึ่ง ไม่ใช่ทางแก้การขาดตัวสร้างโน้ต [DeviceSettings.tonesOn](https://developer.garmin.com/connect-iq/api-docs/Toybox/System/DeviceSettings.html)
- Venu 4 **เล่น MP3/M4A ที่โหลดเข้า Music ผ่านลำโพงนาฬิกาได้** ดังนั้นตัวลำโพงและ decoder ไม่ใช่ข้อจำกัดทางกายภาพ [คู่มือ Venu 4: Music](https://www8.garmin.com/manuals/webhelp/GUID-2CF5620C-E585-4E0A-9CC3-9565533EEE4D/EN-US/GUID-8702C05F-0915-455A-AABA-079D8374FCD8.html), [การโหลดไฟล์ส่วนตัว](https://www8.garmin.com/manuals/webhelp/GUID-2CF5620C-E585-4E0A-9CC3-9565533EEE4D/EN-US/GUID-CD4439DF-46FF-4279-A8D5-8DA61C87A4EB.html)
- `Toybox.Media` มี MP3, M4A และ WAV แต่ระบุประเภทแอปเป็น Audio Content Provider, Background, Glance; ไม่มี Watch App. Audio Content Provider ทำหน้าที่ดาวน์โหลด/แจกไฟล์ให้ **native media player** ไม่ใช่ API เล่น byte buffer หรือไฟล์ภายในฉากเกม `Media.startPlayback()` ออกจากโหมดปัจจุบันของ Audio Content Provider ไปยังโหมด playback [Toybox.Media](https://developer.garmin.com/connect-iq/api-docs/Toybox/Media.html), [AudioContentProviderApp](https://developer.garmin.com/connect-iq/api-docs/Toybox/Application/AudioContentProviderApp.html), [Garmin FAQ](https://developer.garmin.com/connect-iq/connect-iq-faq/how-do-i-create-an-audio-content-provider/). ตัวอย่างทางการของ Garmin ก็แยก [audio-provider](https://github.com/garmin/connectiq-apps/tree/master/audio-provider) จาก [device-apps](https://github.com/garmin/connectiq-apps)
- ตรวจซ้ำด้วย SDK 9.2.0 วันที่ 2 ตุลาคม 2026: โปรแกรมทดสอบ `watch-app` ที่เรียก `Media.startPlayback(null)` **คอมไพล์ผ่าน** ดังนั้นการคอมไพล์ไม่ตรวจขอบเขตชนิดแอปนี้ แต่ยังไม่ได้พิสูจน์ว่าทำงานบน Venu 4 จริง และไม่มี `ContentDelegate`/ไฟล์ของ Audio Content Provider ให้ระบบเล่น เอกสารเมธอดระบุชัดว่ามันออกจากโหมดปัจจุบันของ Audio Content Provider ไปยังโหมด playback จึงไม่ใช่หลักฐานว่า watch-app เล่น MP3 ระหว่างหน้าเกมได้ [Media.startPlayback](https://developer.garmin.com/connect-iq/api-docs/Toybox/Media.html), [ContentDelegate](https://developer.garmin.com/connect-iq/api-docs/Toybox/Media/ContentDelegate.html)

### เหตุใดทางเลี่ยงผ่านระบบเพลงยังไม่ใช่เสียงในเกม

การเปลี่ยนทั้งเกมเป็น Audio Content Provider ไม่ได้เพิ่มเมธอดเล่นไฟล์เสียงจากฉากเกม: `Media.startPlayback()` ส่งการเล่นให้ native media player และออกจากโหมด app ปัจจุบัน การเปิด Audio Content Provider อีกตัวผ่าน intent ก็ไม่ใช่ทางควบคุมเสียงย่อยแบบทันที เพราะ `System.exitTo()` เป็นการ **ออกจากแอปเดิมพร้อมหน้าจอยืนยัน** และเอกสาร intent จำกัดเป้าหมาย Connect IQ ไว้ที่ device app/widget [Media.startPlayback](https://developer.garmin.com/connect-iq/api-docs/Toybox/Media.html), [Garmin: Intents](https://developer.garmin.com/connect-iq/core-topics/intents/). การเตรียมไฟล์ทั้งหมดเป็น playlist ทำให้ *ฟัง* เสียงเดิมได้ แต่ไม่มีทางเลือก track ที่ตรงกับ `battle`, `reward`, `digistorm` ณ จังหวะนั้นจาก watch app ตาม API ที่ตรวจพบ นี่เป็นข้ออนุมานจากขอบเขต API ที่ Garmin เผยแพร่ ไม่ใช่คำยืนยันว่าเฟิร์มแวร์ภายในทำไม่ได้

### จุดที่ควรพิสูจน์ก่อนลงแรง ถ้ารับเสียงจากโทรศัพท์ได้

ทำต้นแบบสั้น ๆ เฉพาะ `charHappy`, `encounter` และ `digistorm`: ใช้ชื่อเสียงที่เกมส่งอยู่แล้ว, ส่งรหัสหนึ่งตัวผ่าน `Communications.transmit()`, ให้แอปคู่เปิด MP3 เดิม, วัดเวลาจากจังหวะวาดภาพบน Venu 4 จริงถึงเสียงเริ่ม และลองขณะหน้าจอโทรศัพท์ล็อก/สลับแอป/หลุด BLE/มีเพลงอื่นเล่น อย่าส่ง MP3 ข้าม BLE ทุกครั้ง เพราะ Garmin อธิบายช่องสื่อสารกับโทรศัพท์ว่ามีแบนด์วิดท์ต่ำมาก; ไฟล์ควรอยู่ในแอปคู่ [Toybox.Communications](https://developer.garmin.com/connect-iq/api-docs/Toybox/Communications.html), [Garmin: REST/BLE bandwidth](https://developer.garmin.com/connect-iq/connect-iq-faq/how-do-i-use-rest-services/). หากเงื่อนไขยังคงเป็น **ลำโพง Venu 4 เท่านั้น** ให้หยุดที่ข้อสรุปว่า API สาธารณะปัจจุบันยังทำไม่ได้ และกลับมาตรวจเมื่อ Garmin เพิ่ม API เล่น arbitrary audio หรือรองรับ `ToneProfile` บน speaker watches จริง [Garmin staff](https://forums.garmin.com/developer/connect-iq/f/discussion/405695/the-toneprofile-does-not-work-on-venu3s/1909456)
